  • Use pre-commit hooks for local lint and formatting feedback.
  • Run lint, formatting, and pytest checks on a pull request using GitHub Actions.
  • Explain a lint failure and repair it without disabling the check (Ruff linter documentation).

Agenda

Configure the tools → run them locally → inspect and fix findings → add CI → demonstrate a failing and repaired pull request.

Main points

Static analysis: Ruff inspects source code without running it.
Formatting: Ruff’s formatter makes presentation consistent.
Tests: pytest executes selected behaviors. Each check answers a different question.

Local hooks and CI: pre-commit catches problems early on your machine. GitHub Actions checks pushed changes independently. Passing checks alone do not enforce merge restrictions; required status checks do.

Adaptation: the source uses Black, Ruff, and notebook cleanup. This exercise uses Ruff for linting and formatting, supplies a small Python example, and keeps notebook-specific tools optional.

2) Run the same checks before each commit

pre-commit is a tool that runs configured checks when you attempt a Git commit. A hook is one of those automatic checks. In this activity, install Ruff’s lint and formatting hooks so you receive feedback before committing. See the pre-commit quick start for reference.

Why use pre-commit when Ruff is already installed? In Activity 1, you ran Ruff manually from your project’s .venv. Here, pre-commit will run Ruff automatically before each commit. It installs its own copy of Ruff in a cache outside the repository, using the version specified by rev in the hook configuration. This makes commit checks independent of whether you have activated .venv. Both installations use the same Ruff version and read the same pyproject.toml, so manual and automatic checks use the same rules.

How this fits a typical development workflow: run Ruff manually while editing to investigate findings and check fixes. Pre-commit runs it automatically when you commit, so you do not have to remember every check. Later in this lab, GitHub Actions runs it again on pushed changes, giving the team a shared result even if a developer skips the local hook. Keeping these checks at all three points is useful: while editing → before committing → on the pull request. Use the same Ruff version and configuration at each point.

Copy lab-assets/pre-commit-config.yaml.example to the repository root and rename it .pre-commit-config.yaml. Read the two hook entries: ruff-check performs lint checks and safe fixes; ruff-format formats the code.

Next, run these commands in your terminal to install the Git hooks, stage your files, and check all tracked files.

Terminal — install hooks
python -m pre_commit install
git add .
python -m pre_commit run --all-files

The first run downloads hook environments and requires internet access. --all-files checks tracked files, including newly staged files. If a hook modifies a file, the check fails: review the changes, stage the file again, and retry. The same hooks will run automatically on subsequent commits in this clone.

Expected output:

ruff check...............................................................Passed
ruff format..............................................................Passed

4) Add GitHub Actions

In this activity, you will configure GitHub Actions to run Ruff lint checks, formatting checks, and pytest automatically. Each check runs as a separate job, so GitHub shows which check passed or failed.

Why is setup repeated? Each job runs on a separate GitHub-hosted machine, so it must check out the repository, set up Python, and install dependencies independently. Keeping three jobs lets you see all three results—for example, lint can fail while formatting and tests still pass.

Step 1. Create the workflow file

Create .github/workflows/ in your repository. Copy lab-assets/ci.yml.example into that folder and rename it ci.yml.

Step 2. Replace the three TODO commands

In .github/workflows/ci.yml, replace each - run: exit 1 # TODO... line with the matching line below. Replace the whole line, keep its existing indentation, and leave the other workflow lines unchanged.

lint job — replace its TODO line
- run: python -m ruff check --output-format=github .  # Report lint findings as GitHub annotations
format job — replace its TODO line
- run: python -m ruff format --check .  # Check formatting without changing files
tests job — replace its TODO line
- run: python -m pytest -q --maxfail=1  # Run tests; stop after the first failure

Step 3. Commit and push the workflow

Save the workflow file, then run these commands in your terminal to commit your work and push it to your fork:

Terminal — publish the working baseline
git add .
git commit -m "Add Ruff checks and CI"
git push -u origin main

Step 4. Check the workflow results

Open your repository’s Actions tab and select the latest CI run. Confirm that lint, format, and tests pass. If prompted, enable GitHub Actions.

Add a record to your report as item 6:

  • Take a screenshot of the GitHub Actions run showing lint, format, and tests passing.
  • Add the screenshot and the URL of that specific Actions run to your PDF report. Copy the URL while viewing the run, not the repository’s general Actions page.

Optional: require successful checks before merging

Configure this in your own fork, after the Activity 4 workflow has run. If you already created an equivalent ruleset, edit that ruleset instead of creating another.

  1. Open Settings → Rulesets → Rulesets in the left sidebar. In some GitHub layouts, this appears as Rules → Rulesets.
  2. Click New ruleset → New branch ruleset.
  3. Enter require-ci-on-main as the Ruleset Name.
  4. Change Enforcement status from Disabled to Active.
  5. Leave the Bypass list empty.
  6. Under Target branches, click Add target → Include default branch. Confirm the target is your fork’s main branch.
  7. Under branch rules or protections, select Require a pull request before merging. Set Required approvals to 0 for this individual exercise.
  8. Select Require status checks to pass. Expand Show additional settings if needed. Leave Require branches to be up to date before merging and Do not require status checks on creation unchecked. In Required status checks, click Add checks. Enter lint and select its checkbox. Repeat for format and tests. Confirm all three names appear in the required-checks list.
  9. Leave the other options unchanged and click Create (or Save changes when editing). Confirm require-ci-on-main is listed as Active.

Verify the rule: open the failing pull request described below. The failed lint check should prevent merging. Capture the failed required check and blocked merge before repairing the code. A red check reports a failure; this ruleset makes passing checks a merge requirement.

Reference: GitHub’s ruleset instructions.
