Learning goals

  • Configure Ruff to detect common Python problems and organize imports (rule reference).
  • Use pre-commit hooks for local lint and formatting feedback.
  • Run lint, formatting, and pytest checks on a pull request using GitHub Actions.
  • Explain a lint failure and repair it without disabling the check (Ruff linter documentation).

Agenda

Configure the tools → run them locally → inspect and fix findings → add CI → demonstrate a failing and repaired pull request.

Main points

Static analysis: Ruff inspects source code without running it.
Formatting: Ruff’s formatter makes presentation consistent.
Tests: pytest executes selected behaviors. Each check answers a different question.

Local hooks and CI: pre-commit catches problems early on your machine. GitHub Actions checks pushed changes independently. Passing checks alone do not enforce merge restrictions; required status checks do.

Adaptation: the source uses Black, Ruff, and notebook cleanup. This exercise uses Ruff for linting and formatting, supplies a small Python example, and keeps notebook-specific tools optional.

2) Run the same checks before each commit

pre-commit is a tool that runs configured checks when you attempt a Git commit. A hook is one of those automatic checks. In this activity, install Ruff’s lint and formatting hooks so you receive feedback before committing. See the pre-commit quick start for reference.

Why use pre-commit when Ruff is already installed? In Activity 1, you ran Ruff manually from your project’s .venv. Here, pre-commit will run Ruff automatically before each commit. It installs its own copy of Ruff in a cache outside the repository, using the version specified by rev in the hook configuration. This makes commit checks independent of whether you have activated .venv. Both installations use the same Ruff version and read the same pyproject.toml, so manual and automatic checks use the same rules.

How this fits a typical development workflow: run Ruff manually while editing to investigate findings and check fixes. Pre-commit runs it automatically when you commit, so you do not have to remember every check. Later in this lab, GitHub Actions runs it again on pushed changes, giving the team a shared result even if a developer skips the local hook. Keeping these checks at all three points is useful: while editing → before committing → on the pull request. Use the same Ruff version and configuration at each point.

Copy lab-assets/pre-commit-config.yaml.example to the repository root and rename it .pre-commit-config.yaml. Read the two hook entries: ruff-check performs lint checks and safe fixes; ruff-format formats the code.

Next, run these commands in your terminal to install the Git hooks, stage your files, and check all tracked files.

Terminal — install hooks
python -m pre_commit install
git add .
python -m pre_commit run --all-files

The first run downloads hook environments and requires internet access. --all-files checks tracked files, including newly staged files. If a hook modifies a file, the check fails: review the changes, stage the file again, and retry. The same hooks will run automatically on subsequent commits in this clone.

Expected output:

ruff check...............................................................Passed
ruff format..............................................................Passed

3) Investigate a real lint finding

This sample contains problems that the existing tests do not detect. First record Ruff’s findings and compare them with the test results.

Replace the contents of calculator.py with lab-assets/calculator-bugs.py.txt. Keep the destination filename calculator.py; the sample is stored as text so it does not interfere with baseline checks.

Run Ruff and the tests. Run the following commands one at a time in your terminal:

Terminal — inspect findings before fixing
python -m ruff check calculator.py
python -m pytest -q

Compare the results: does Ruff report findings even though the tests pass?

Ruff should report F401 (unused import), F841 (unused variable), and B006 (mutable default argument).

Prepare for submission

  • Take a screenshot of the output from python -m ruff check calculator.py. Include the command and all three findings: F401, F841, and B006. Add this screenshot to your PDF report.

The two tests still pass because they only exercise add.

Next, apply Ruff’s safe fixes. Run python -m ruff check --fix calculator.py.

Prepare for submission

  • Take a screenshot of the command python -m ruff check --fix calculator.py and its output. Add this screenshot to your PDF report.

Compare the findings: the safe fix removes the import but leaves the other two issues for you to resolve.

Before repairing record, add a regression test in test_calculator.py. Import record, call it twice without supplying a history, and assert that each result contains only the value from that call. Run python -m pytest -q and confirm the new test fails. A regression test captures a bug so it can be detected if it returns.

Repair the remaining findings yourself: remove the unused assignment, and replace the shared mutable default with a fresh list when no history is supplied. Preserve support for a caller-provided history list.

Hint: why does the default list cause a bug?

Python creates a default argument value once, when the function is defined. A default list can therefore be shared by later calls. Use None to represent an omitted history, then create a new list inside the function only in that case. Keep a history explicitly supplied by the caller.

After repairing the function and adding your test, run these commands in your terminal to format the code and verify the result.

After formatting, git diff shows your changes since the last commit: - lines show the previous version and + lines show the new version. Check your repair and formatting changes before staging them. Press q to exit if the diff opens in a pager.

Terminal — finish the repair
python -m ruff check --fix .
python -m ruff format .
git diff
git add .
python -m pre_commit run --all-files
python -m pytest -q

Checkpoint: lint and formatting pass, and the two baseline tests plus your regression test pass. Explain why the mutable default can leak values between calls.

4) Add GitHub Actions

Complete the CI template so lint, formatting, and tests run as separate jobs. CI must report problems without automatically changing files.

Create .github/workflows/ and copy lab-assets/ci.yml.example to .github/workflows/ci.yml. Open this destination file in your editor. Replace only the three run: exit 1 # TODO... lines, preserving their indentation and all other steps. For example, the formatting line becomes - run: python -m ruff format --check .. Complete the lint line using python -m ruff check --output-format=github . and the test line using python -m pytest -q --maxfail=1. The annotations option lets GitHub display findings beside code; the pytest option stops after the first failure.

After completing the workflow, run these commands in your terminal to commit your work and push it to your fork.

Terminal — publish the working baseline
git add .
git commit -m "Add Ruff checks, regression test, and CI"
git push -u origin main

Open the repository’s Actions tab. Wait for lint, format, and tests to pass before continuing. If GitHub asks you to enable Actions, enable it and rerun the workflow. If no run appears after enabling Actions, open the workflow in the Actions tab and check whether GitHub offers a rerun. If no run exists, make an empty commit with git commit --allow-empty -m "Trigger CI" and push again.

Prepare for submission

  • Keep the completed .github/workflows/ci.yml in your fork. The passing result captured in Activity 5 will provide your final CI evidence.

5) Make CI catch a failing pull request

In your terminal, run this command to create and switch to a branch for the deliberate defect.

Terminal — new branch
git switch -c demonstrate-ruff

Append this function to calculator.py. The name missing_total is undefined.

calculator.py — append deliberate defect
def broken_total():
    return missing_total

After adding the function above, run these commands one at a time in your terminal. The lint check and commit attempt are expected to fail.

Terminal — observe the failure
python -m ruff format calculator.py
python -m ruff check .
python -m pytest -q
git add calculator.py
git commit -m "Demonstrate undefined-name detection"

Ruff reports F821, but tests pass because they never call broken_total. The local lint hook rejects the commit. For this demonstration only, the next command temporarily points Git to lab-assets, which contains no Git hooks, so the failing code can reach CI. This applies to this one commit and does not disable hooks for later commits.

Next, run these commands in your terminal to commit the deliberate defect for this demonstration and push the branch.

Terminal — demonstration only
git -c core.hooksPath=lab-assets commit -m "Demonstrate CI lint failure"
git push -u origin demonstrate-ruff
Optional: require successful checks before merging

In repository Settings → Rules → Rulesets, create an active branch ruleset targeting the default branch. Require a pull request and the lint, format, and tests status checks, leaving required approvals at zero for this individual exercise. Keep the bypass list empty. Checks must have run before GitHub can offer them. A red check reports a failure; a required-check rule is what blocks merging. Capture the blocked merge before fixing the PR if you do this extension.

Open a pull request from demonstrate-ruff into your own fork’s main branch. GitHub may initially suggest the instructor repository; change the base repository to your fork. Capture the failed lint job and its F821 message; format and tests should pass. If doing the optional merge-protection exercise above, capture the blocked merge now. Then delete broken_total and run the repair commands below.

After deleting the broken function, run these commands in your terminal to verify the repair and update the same pull request.

Terminal — fix the same pull request
python -m ruff format .
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
git add calculator.py
git commit -m "Remove undefined-name defect"
git push

Checkpoint: the same pull request now has three passing jobs. Local hooks provide early feedback; CI still checks changes when a hook is skipped.

Prepare for submission

  • Save the pull request URL.
  • Capture the failed lint job showing F821 before repairing it.
  • After the repair, capture the same PR with lint, format, and tests passing.
  • Explain F821, why the tests passed with the undefined name, and why passing Ruff checks cannot guarantee correct behavior.
  • If you completed the optional merge-protection task, save a screenshot of the blocked merge.
