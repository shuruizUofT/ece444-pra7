Reading: Before starting the activities, read the Ruff tutorial for an introduction to linting, fixing findings, and formatting Python code.

Learning goals

  • Configure Ruff to detect common Python problems and organize imports.
  • Use pre-commit hooks for local lint and formatting feedback.
  • Run lint, formatting, and pytest checks on a pull request.
  • Explain a lint failure and repair it without disabling the check.

Agenda

Configure the tools → run them locally → inspect and fix findings → add CI → demonstrate a failing and repaired pull request.

Main points

Static analysis: Ruff inspects source code without running it. Formatting: Ruff’s formatter makes presentation consistent. Tests: pytest executes selected behaviors. Each check answers a different question.

Local hooks and CI: pre-commit catches problems early on your machine. GitHub Actions checks pushed changes independently. Passing checks alone do not enforce merge restrictions; required status checks do.

Adaptation: the source uses Black, Ruff, and notebook cleanup. This exercise uses Ruff for linting and formatting, supplies a small Python example, and keeps notebook-specific tools optional.

Activities

0) Prepare your fork

Complete the starter README’s setup instructions. It contains the fork and clone steps, environment setup, dependency installation, and Windows commands.

Before continuing: both baseline tests pass, your environment is active, and your clone points to your own fork.

1) Configure static analysis and formatting

Create this configuration. Ruff checks source code without executing it. The E and F families catch selected code errors, I checks import ordering, and B adds bug-prone patterns. Formatting is a separate operation.

Copy lab-assets/pyproject.toml.example to pyproject.toml in the repository root. Read the selected rules and explain what each family checks.

Repository file: pyproject.toml.example (use GitHub’s Raw view to copy or download).

Terminal — baseline checks
python -m ruff check .
python -m ruff format --check .

If formatting fails, run python -m ruff format ., inspect the changes, and rerun both commands. A clean lint report does not prove the program is correct; the tests check behavior separately.

2) Run the same checks before each commit

Create a pre-commit configuration. The first hook can repair safe lint findings; the second formats Python files. We use Ruff for both jobs, so a second formatter is unnecessary.

Copy lab-assets/pre-commit-config.yaml.example to .pre-commit-config.yaml in the repository root. Identify which hook performs lint fixes and which formats the code.

Repository file: pre-commit-config.yaml.example (use GitHub’s Raw view to copy or download).

Terminal — install hooks
python -m pre_commit install
git add .
python -m pre_commit run --all-files

Pre-commit checks tracked or staged files. Stage new files before using --all-files. Its first run downloads hook environments and needs internet access. When a hook changes a file, review it, stage it again, and rerun the check.

Checkpoint: both Ruff hooks pass.

3) Investigate a real lint finding

Use the deliberately flawed sample from the repository for this activity.

Replace the contents of calculator.py with lab-assets/calculator-bugs.py.txt. Keep the destination filename calculator.py; the sample is stored as text so it does not interfere with baseline checks.

Repository file: calculator-bugs.py.txt (use GitHub’s Raw view to copy or download).

Terminal — inspect findings before fixing
python -m ruff check calculator.py
python -m pytest -q
python -m ruff check --fix calculator.py
python -m ruff format calculator.py

The first lint command should fail with F401 (unused import), F841 (unused variable), and B006 (mutable default argument). The two existing tests still pass because they do not exercise record. Safe automatic fixes remove the import, but leave findings that need your judgment.

Repair the remaining findings yourself: remove the unused assignment, and replace the shared mutable default with a fresh list when no history is supplied. Preserve support for a caller-provided history list.

Write a regression test in test_calculator.py that calls record twice without supplying a history. Assert that each call returns only its own value. Update the import to include record. Run this test against the flawed function first to confirm it fails, then verify it passes after your repair.

Terminal — finish the repair
python -m ruff check --fix .
python -m ruff format .
git add .
python -m pre_commit run --all-files
python -m pytest -q

Checkpoint: lint and formatting pass, and the two baseline tests plus your regression test pass. Explain why the mutable default can leak values between calls.

4) Add GitHub Actions

Complete the CI template so lint, formatting, and tests run as separate jobs. CI must report problems without automatically changing files.

Create .github/workflows/ and copy lab-assets/ci.yml.example to .github/workflows/ci.yml. Replace each of the three exit 1 placeholders with the appropriate command: report Ruff lint findings with GitHub annotations; check formatting without changing files; run pytest and stop after the first failure. Use the commands from the earlier activities as a reference.

Repository file: ci.yml.example (use GitHub’s Raw view to copy or download).

Terminal — publish the working baseline
git add .
git commit -m "Add Ruff checks, regression test, and CI"
git push -u origin main

Open the repository’s Actions tab. Wait for lint, format, and tests to pass before continuing. If GitHub asks you to enable Actions, enable it and rerun the workflow.

5) Make CI catch a failing pull request

Create a new branch:

Terminal — new branch
git switch -c demonstrate-ruff

Append this function to calculator.py. The name missing_total is undefined.

calculator.py — append deliberate defect
def broken_total():
    return missing_total
Terminal — observe the failure
python -m ruff format calculator.py
python -m ruff check .
python -m pytest -q
git add calculator.py
git commit -m "Demonstrate undefined-name detection"

Ruff reports F821, while the tests still pass. The commit is rejected by the local hook. To demonstrate the independent CI check, use the following once, only on this exercise branch:

Terminal — demonstration only
git -c core.hooksPath=/dev/null commit -m "Demonstrate CI lint failure"
git push -u origin demonstrate-ruff

Open a pull request from demonstrate-ruff into your repository’s main. Capture the failing lint job and its F821 message. The formatting and test jobs should pass. Delete broken_total, then run:

Terminal — fix the same pull request
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
git add calculator.py
git commit -m "Remove undefined-name defect"
git push

Checkpoint: the same pull request now has three passing jobs. Local hooks provide early feedback; CI still checks changes when a hook is skipped.

Optional: require successful checks before merging

In repository Settings → Rules → Rulesets, create an active branch ruleset targeting the default branch. Require a pull request and the lint, format, and tests status checks, leaving required approvals at zero for this individual exercise. Keep the bypass list empty. Checks must have run before GitHub can offer them. A red check reports a failure; a required-check rule is what blocks merging. Capture the blocked merge before fixing the PR if you do this extension.

6) Verify from a fresh clone and submit

In a different directory, follow the README setup instructions to create a fresh clone and environment. Use a different local folder name or parent directory to avoid overwriting your working copy. Then switch to your repaired branch and verify its hooks and tests:

Terminal — fresh-clone check
git switch demonstrate-ruff
python -m pre_commit install
python -m pre_commit run --all-files
python -m pytest -q

Keep the repaired PR branch available until this check is complete; if already merged and deleted, use main instead of demonstrate-ruff. Git hooks are local to each clone, so install them again as shown above.

Wrap-up

You have connected local feedback to remote CI: Ruff identifies selected source-level problems, formatting checks keep presentation consistent, and pytest checks expected results. Your failed and repaired PR provides evidence that the pipeline works.

Key points

  • If a hook modifies files, inspect the changes and stage them again.
  • If pre-commit finds no files, make sure your Python files are tracked or staged.
  • Use the same pinned Ruff release locally, in hooks, and in CI.
  • Do not use automatic fixes in CI to hide a failing check; fix and commit locally.
  • A test suite can pass while Ruff finds a defect, and Ruff can pass while behavior is wrong.
Optional: keep notebook output out of commits

If you apply this workflow to a notebook project, follow the source lab’s notebook-cleanup steps to add nbstripout. Notebook tooling is not needed for this calculator exercise.
